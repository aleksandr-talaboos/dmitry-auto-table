# Библиотека A/B-тестов — автообновление вкладки в Google Таблице (DEV-347), версия под Vercel

> ⚠️ **Важно, прочитайте сначала.** Это адаптация нашего рабочего скрипта под Vercel, сделанная **навскидку**
> специально для Дмитрия. В таком виде (Vercel + Upstash Redis + свой вход в CampaignsWell) код **вживую не
> проверялся**. У нас та же логика работает внутри долгоживущего Docker-сервиса на собственном сервере, с общим
> шлюзом запросов к Binom, файлами состояния и базой Postgres. Здесь всё это **намеренно** заменено на то, что есть
> на Vercel.
>
> Расчёт строк и оформление вкладки перенесены без изменений. «Обвязка» (запуск по расписанию, хранение состояния,
> вход в CW, ключ Google) написана заново, и в ней возможны недочёты. Поэтому первые запуски делайте в режиме
> `dry-run`, без записи в таблицу, и сверяйте результат с нашей вкладкой.
>
> Что проверено: расчёт этой версии один раз прогнали на реальных данных за 2026-11-08 в режиме dry-run (на нашем
> сервере, локальный CLI, без Vercel и Redis). Результат совпал с нашей рабочей вкладкой:
> - все 76 строк, их порядок, контроль и варианты совпали;
> - расхождения только в 1–2 покупках и подписках, которые дошли за день между прогонами.
>
> Сама функция Vercel, cron, Redis и запись в таблицу этой версией не запускались.

## Что делает

Раз в день собирает отчёт по **всем A/B-тестам** за весь срок кампании. Тестами считаются кампании Binom с `E…`,
`[TEST…]` или словом `test` в названии, кроме `[MAIN]` и bots-trap. Отчёт полностью перезаписывает одну вкладку
таблицы [«Библиотека A/B-тестов»](https://docs.google.com/spreadsheets/d/19YZepTyW95fN-ghCUmNxUOMgFCXUS4vlrZi9l9hhu08/edit).

- **Строки.** Отсортированы по числу покупок кампании, есть отдельная колонка «покупок за 3 дня». По каждому тесту:
  статус (идёт / стоп с даты / нет трафика), дата старта, контроль и вариант. Если вариантов несколько — по строке
  на вариант.
- **Четыре блока сравнения:** покупка/клик (CVR), выручка/клик, pLTV за 3 месяца (прогноз CW), trial→paid (Binom).
- **Правила выводов** (из черновика Димы и нашего A/B-анализа):
  - CVR — двухдолевой z-тест, 90% интервал. Значимо при p < 0,10 и не меньше 30 покупок на плечо. При нескольких
    вариантах — поправка Холма.
  - Выручка и pLTV — порог ±5%.
  - Trial→paid — по статусам Binom payer/subscriber в «созревших» когортах, минимум 10 плательщиков.
- **Какие плечи учитываются:** не меньше 100 уникальных кликов и не меньше 5% трафика кампании.
- **Колонка «Вывод»** подсвечена: зелёный — лучше, красный — хуже, жёлтый — мало данных, серый — сравнить нельзя.
  Как считается каждая колонка, видно во всплывающей заметке на заголовке.
- **Расписание (UTC):**
  - 02:00 — предварительный проход. В первой строке вкладки янтарная пометка «Предварительно…»: покупки Binom за
    вчера уже полные, а подписки и pLTV из CW догружены примерно наполовину.
  - 06:30 — окончательный проход.
  - 08:30 — повтор окончательного, если в 06:30 он не прошёл или прошёл без CW. Если всё прошло, повтор пропускается.

Все даты — дни UTC, отчёт строится только за полностью прошедший день (по умолчанию вчерашний).

Вкладка перезаписывается целиком при каждом проходе, ручные правки в ней не сохраняются.

### Google Cloud: сервисный аккаунт по шагам

1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект (или взять свой).
2. APIs & Services → Library → **Google Sheets API** → Enable.
3. IAM & Admin → Service Accounts → Create service account. Роли в проекте не нужны.
4. Открыть созданный аккаунт → Keys → Add key → JSON. Скачается файл с ключом. Его **не коммитить**: `.gitignore`
   уже исключает `*service-account*.json` и `credentials*.json`, но лучше держать ключ вне папки проекта.
5. Скопировать `client_email` из файла и попросить для него роль «Редактор» в таблице (текст запроса выше).
6. В переменную `GOOGLE_SERVICE_ACCOUNT_JSON` положить содержимое файла целиком. Если многострочный JSON неудобно
   вставлять, подойдёт base64 от файла: `base64 -w0 key.json` (macOS: `base64 -i key.json`).

Если создание ключей запрещено политикой организации (`iam.disableServiceAccountKeyCreation`), ключ выпускает
администратор Google Workspace. Либо проект создаётся вне организации.

## Переменные окружения

Полный список с комментариями — в `.env.example`. Ничего из этого не коммитьте. В Vercel секреты добавляйте только в
окружение **Production**: cron вызывает только production-деплой, а превью-сборкам ключи не нужны.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `CRON_SECRET` | да | случайная строка не короче 32 символов (`openssl rand -hex 32`). Vercel Cron передаёт её в заголовке `Authorization`, ручные вызовы — тоже с ней. Задать **до первого деплоя**. |
| `BINOM_BASE_URL`, `BINOM_API_KEY` | да | адрес трекера Binom и API-ключ |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | для записи | JSON-ключ сервисного аккаунта целиком или base64 от него |
| `LIBRARY_SPREADSHEET_ID` | для записи | `19YZepTyW95fN-ghCUmNxUOMgFCXUS4vlrZi9l9hhu08` |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | да на Vercel | добавляются интеграцией Upstash. Подходят и имена `KV_REST_API_URL`/`KV_REST_API_TOKEN`, которые ставит Vercel Marketplace |
| `LIBRARY_MODE` | нет | `dry-run` (по умолчанию: считать без записи) / `write` / `off`. У нас по умолчанию `off` |
| `LIBRARY_SHEET_TITLE` | нет | имя своей вкладки. По умолчанию «Драфт отчета по всем тестам - авто (Vercel)», создаётся при первой записи |
| `LIBRARY_SHEET_GID` | нет | gid уже существующей вкладки вместо имени (тогда её можно переименовывать) |
| `LIBRARY_DEADLINE_SECONDS` | нет | через сколько секунд прогон сам останавливается и снимает блокировку. По умолчанию 270 при `maxDuration` 300. На Pro с `maxDuration` 800 поставьте 770 |
| `LIBRARY_ALERT_WEBHOOK_URL` | нет | входящий вебхук Slack (`https://hooks.slack.com/...`) или любой сервис, который принимает `{"text": "..."}`. Туда уходят упавшие прогоны и окончательные проходы без CW |
| `LIBRARY_REQUEST_BUDGET` | нет | предел запросов к Binom за прогон. По умолчанию 80 (у нас 60: наш сервис берёт часть данных из общего кеша) |
| `LIBRARY_FROM`, `LIBRARY_DAYS_CHUNK`, `LIBRARY_ALIASES`, `LIBRARY_PAID_LAG_DAYS`, `LIBRARY_BASE_OFFER_OVERRIDES`, `LIBRARY_REGISTRY_TAB`, `LIBRARY_ARCHIVE` | нет | значения по умолчанию совпадают с нашими (начало окна 2026-06-01, сроки созревания trial→paid и т. д.) |
| `CW_SERVER_URL` | нет | адрес MCP-сервера CW для `npm run cw:login`. Функция берёт адрес из сохранённого токена |
| `CW_REFRESH_DISABLED` | нет | `true` — не обновлять токен CW (только для отладки) |

## Развёртывание по шагам

Нужно заранее: Node.js 22, git, аккаунт Vercel и Vercel CLI (`npm i -g vercel`, для `vercel env pull`). Плюс доступы
из таблицы выше: Binom, CW, Google.

1. `git clone` этого репозитория, затем `npm ci`.
2. В Vercel: Add New → Project → импортировать репозиторий. Framework Preset — **Other**, сборку не настраивать.
   До первого деплоя добавить в Settings → Environment Variables (Production) переменную `CRON_SECRET`.
3. Подключить Redis: Storage → Upstash Redis → создать и привязать к проекту. Переменные `KV_REST_API_URL` и
   `KV_REST_API_TOKEN` (или `UPSTASH_REDIS_REST_*`) появятся в проекте сами.
4. Локально: `vercel link`, затем `vercel env pull .env --environment=production`. Это положит в `.env` переменные
   Redis и `CRON_SECRET`. Другой путь — скопировать REST URL и токен из консоли Upstash (база → REST API).
   Дописать в `.env` по образцу `.env.example`: `BINOM_BASE_URL`, `BINOM_API_KEY`, `GOOGLE_SERVICE_ACCOUNT_JSON`,
   `LIBRARY_SPREADSHEET_ID`.
5. `npm run cw:login`. Запускать на том же компьютере, где открывается браузер: вход возвращается на
   `http://127.0.0.1:<порт>`. Войдите в CampaignsWell своим пользователем. В конце должна появиться строка
   `CampaignsWell credentials saved to Upstash Redis`. Без настроенного Redis команда остановится с подсказкой.
   Возможные ошибки:
   - `OAuth login timed out` — вход не завершён за 15 минут;
   - `OAuth returned access_denied` — у пользователя нет доступа к CW;
   - страница «callback … was ignored» — открыта старая вкладка входа; завершите вход в новой.
6. Первый прогон — локально, без записи:
   `npm run run:local -- --dry-run --csv out.csv` (по умолчанию за вчера; `--date YYYY-MM-DD` — за другой день).
   Первый прогон «холодный»: около 60 запросов к Binom и 3–4 минуты. Он заполняет историю плеч и кеш родительских
   кампаний в Redis, дальше прогон занимает около 15 запросов и минуты. В конце печатается сводка: `rows` около 75,
   `warnings` пустые, `complete: true`. Сверьте `out.csv` с нашей вкладкой.
7. В Vercel → Settings → Environment Variables (Production) добавить переменные из `.env`, кроме Redis (они уже есть).
   Добавить `LIBRARY_MODE=dry-run`, затем Deployments → Redeploy.
8. Проверка на Vercel без записи (адрес — production-домен проекта):

   ```bash
   curl -sS -D - -H "Authorization: Bearer <CRON_SECRET>" "https://<проект>.vercel.app/api/run?pass=final&dryRun=1" -o vercel.csv
   ```

   В ответ придёт CSV, а в заголовке `X-Library-Summary` — та же сводка. Если вместо JSON `{"error":"Unauthorized"}`
   пришла HTML-страница входа Vercel, мешает Deployment Protection. Вызывайте production-домен или включите
   Protection Bypass for Automation и передайте заголовок `x-vercel-protection-bypass`.
9. Включить запись: `LIBRARY_MODE=write`, Redeploy. Расписание из `vercel.json` подхватится само (Settings → Cron
   Jobs; cron работает только в production-деплое). На плане Pro можно поднять `maxDuration` в `vercel.json` до 800
   и `LIBRARY_DEADLINE_SECONDS` до 770.

Ручной перезапуск дня: `.../api/run?pass=final&date=YYYY-MM-DD&force=1` с тем же заголовком.

## Как понять, что всё работает

- В таблице появилась вкладка «Драфт отчета по всем тестам - авто (Vercel)». В её первой строке дата обновления, после
  06:30 UTC — без янтарной пометки «Предварительно».
- Vercel → Logs → `/api/run`: ответ `200` со сводкой `{"rows": …, "complete": true, "warnings": []}`.
- Ответы функции:

| Ответ | Что значит | Что делать |
|---|---|---|
| `200` и сводка, `complete: true` | вкладка записана | ничего |
| `200` и `complete: false` | записано без данных CW (pLTV пустые); окончательный проход не засчитан, следующий cron повторит | проверить CW: возможно, нужен повторный `npm run cw:login` |
| `200 {"skipped": "final-done"}` | окончательный проход за этот день уже был | ничего; для перезаписи — `force=1` |
| `409` | идёт другой прогон, или предыдущий оборвался и блокировка ещё не истекла (не дольше `LIBRARY_DEADLINE_SECONDS` + 60 с) | подождать пару минут |
| `401` | нет или неверный `CRON_SECRET` | проверить заголовок |
| `500` и `errorId` | прогон упал | найти `errorId` в Vercel → Logs; если задан вебхук, туда придёт сообщение |

## Отличия от нашей версии и известные риски

- Контроль выбирается без шага DEV-334, поэтому в отдельных тестах контроль (а значит и вывод) может отличаться от
  нашей вкладки. Если не удалось прочитать родительскую кампанию из Binom, контроль берётся по T-номеру. Тогда в
  примечаниях строки появляется «Контроль по T-номеру: кампания-родитель не прочитана из Binom».
- Код обвязки (функция, Redis, вход в CW, ключ Google) написан под Vercel и живьём не запускался, см. предупреждение
  в начале.
- Время работы, измеренное на нашем сервере: холодный прогон — 61 запрос и около 3,3 мин, обычный — 15 запросов и
  около 1 мин. На Vercel может быть дольше. Прогон останавливается сам за 30 с до предела функции. История плеч
  сохраняется по частям, поэтому следующий прогон продолжает с места обрыва.
- Токен CW меняется при каждом обновлении, примерно раз в день. Функция обновляет его в начале прогона. Не копируйте
  токен между окружениями и не используйте токен Talaboos. Если обновление сорвалось, CW-колонки будут пустыми с
  пометкой «CW недоступен», а повторный `npm run cw:login` всё чинит.
- Binom: не чаще 1 запроса в 2,5 с, бюджет 80 запросов на прогон. Не ставьте cron чаще — это лишняя нагрузка на общий
  трекер.
- Без вебхука упавший прогон виден только в Vercel → Logs: вкладка просто останется вчерашней.
